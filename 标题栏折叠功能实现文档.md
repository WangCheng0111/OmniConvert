# OmniConvert 标题栏折叠(上滑收起)功能实现文档

本文档完整记录「标题栏折叠按钮:点击后标题栏上滑收起、客户区顶满窗口」功能的全部改动与精确代码,供照此复现完全一致的功能。

## 功能概述

- 标题栏新增**折叠按钮**(位于设置按钮左侧、样式与设置按钮一致、上箭头 `\uE70E`)
- 点击后标题栏折叠收起:**高度 48→0** + **内容上滑 24px** + **同步淡出**,三段动画同一 Storyboard、同一时长、同为 CubicEase EaseOut(200ms)
- 客户区内容**不参与任何动画**,随网格自然顶到窗口顶部
- 折叠后:最小化/最大化/关闭三个金刚键与设置按钮**完全失效**(非客户区区域清空 + 执行层防御双保险),窗口顶部不可拖动;**无恢复按钮**(单向折叠,重启应用恢复)
- 折叠按钮参与窗口**失焦/激活变暗动画**(与设置按钮一致)

## 前置注意

1. 本实现依赖项目已有的自定义标题栏体系:`MainWindow.TitleBar.cs`(InputNonClientPointerSource 区域注册)、`MainWindow.NonClient.cs`(窗口子类处理金刚键消息)、`MainWindow.xaml`(AppTitleBar 布局)
2. 若目标项目的 `TitleBarSettingsButtonStyle`/`AppTitleBar`/`MinimizeButton` 等命名不同,需按实际名称适配
3. 折叠为**单向**操作(无恢复入口),如需恢复功能请另行设计

## 五、实现原理与踩坑记录(必读,不可省略)

1. **上滑位移必须取 -24(内容高度 48 的一半)而不是 -48**:折叠时高度与上滑同时进行,内容底边位置 = `48 - 进度f × (24 + Y位移)`。若 Y 位移取 -48,内容在 f=2/3 时就完全出画,而 CubicEase EaseOut 曲线在 **t≈31%** 就达到 f=2/3——肉眼看到的"滑完"只用了约三分之一的时长,之后透明度还在慢慢降,出现"滑完了还很浓"的错位。取 -24 后,内容最后一像素在 **f=1(动画终点)** 才越过窗口顶边,与透明度归 0 严格同时发生
2. **先清空区域再播动画**:`CollapseTitleBar` 里先调 `SetRegionsForCustomTitleBar()`(折叠分支清空全部非客户区),保证动画期间金刚键立即失效
3. **金刚键要双重防御**:区域清空是第一道防线;`MainWindow.NonClient.cs` 四个处理器里的 `_isTitleBarCollapsed` 守卫是第二道防线
4. **失焦动画 bug**:`_captionButtons` 数组驱动窗口失焦/激活时的按钮图标变暗/恢复动画,新增按钮必须加入该数组,否则失焦时它不变灰(与设置按钮不一致)
5. **折叠守卫放在 AppTitleBar_SizeChanged**:折叠动画每帧触发 SizeChanged,加 `_isTitleBarCollapsed` 守卫避免动画期间反复重算区域
6. **折叠后无恢复入口**:标题栏已收起、无任何按钮,窗口不可拖动、不可关闭(重启应用恢复)——这是当前产品决策,如需恢复功能(悬浮按钮/快捷键)需另行开发

## 六、验证步骤

1. 编译:`dotnet build OmniConvert.slnx`(0 错误)
2. 运行:点标题栏折叠按钮(设置按钮左侧、上箭头)
3. 观察:标题栏 200ms 内高度收至 0、内容上滑 24px 并同步淡出(滑完瞬间完全透明),客户区内容自然顶满窗口
4. 折叠动画中与折叠后:点击原金刚键位置均无任何反应(不最小化/最大化/关闭),窗口顶部不可拖动
5. 折叠前:窗口失焦时折叠按钮图标与设置按钮同步变灰,激活时同步恢复
